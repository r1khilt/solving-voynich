# Reading-action memory failure: separate mathematical equivalence from sustained backend admission

## Observed failure and scope

SOURCE-ACTION-TRAIN-001 was actually launched under its frozen published revision. All four 96,039,982-parameter arms failed with a Metal out-of-memory error after 35, 32, 100 and 37 updates. The two earlier admission campaigns passed their registered workloads: five maximum-shape updates and full/cached inference comparisons. They did not test sustained updates with hundreds of different batch geometries. The failed fits sampled variable observed length and variable target-path length and packed each batch to its own maxima. No sufficiently trained checkpoint survived; only step-zero checkpoints exist. No inverse-capacity, language or circuit conclusion follows from the partial training losses.

The resource cap remains in effect. The error's suggestion to disable the allocator limit is not adopted. The original campaign stays closed, with all four failures retained. Changes below are separately named and prospectively qualified; original frozen code, inputs and outcomes are not modified or restarted.

## Source-based engineering hypothesis

PyTorch's [driver-memory API](https://docs.pytorch.org/docs/2.14/generated/torch.mps.driver_allocated_memory.html) includes cached allocator and framework allocations. Its [empty-cache API](https://docs.pytorch.org/docs/2.14/generated/torch.mps.empty_cache.html) documents release of unused allocator memory. Installed Python 2.14.0 calls the native `_mps_emptyCache` function; local version git identity is 08187d9e0fba026dc8217405802ab5381dc88d90. The versioned [allocator](https://github.com/pytorch/pytorch/blob/v2.14.0/aten/src/ATen/mps/MPSAllocator.mm), [graph cache](https://github.com/pytorch/pytorch/blob/v2.14.0/aten/src/ATen/native/mps/OperationUtils.h) and [Python bridge](https://github.com/pytorch/pytorch/blob/v2.14.0/torch/csrc/mps/Module.cpp) were inspected. The allocator frees cached buffers; graph storage has an explicit clear operation. Do not infer complete binary behavior or every memory cause from a Python stub or current-main source alone.

The first-party [varying-shape report](https://github.com/pytorch/pytorch/issues/181213) documents memory growth and separates tensor, driver and process counters. The [current migration issue](https://github.com/pytorch/pytorch/issues/187455), updated September 30, cautions that a remaining cached-graph operation does not by itself establish a growth bug. Historical issue summaries conflict about when empty-cache gained graph eviction; prefer the installed/versioned implementation and measured behavior. Our failure could involve buffer fragmentation, graph retention or other shape-dependent allocation. Its exact cause is not yet established.

Fixed shapes worked in the older whole-key training program. A bounded fixed-geometry representation is therefore a concrete candidate, preserving this new reading objective rather than reducing model size or changing the source task. An allocator cleanup policy is a separately measured engineering comparison. Neither workaround is assumed to pass from literature.

## Proposed fixed training packer and equivalence argument

`source_action_static_pack.static_pack` runs the unchanged literal feature/trajectory validation on CPU using only the original configuration schema. It pads both observed records to the already declared maximum 448 glyphs and supervised queries to 448 source actions, then performs the same eight device transfers with constant dimensions. Actual source targets are two 64–224-letter records, hence at most 448 supervised actions; free generation may still use 896 actions and is not changed by this packer.

Padded glyphs use the existing glyph padding index and are excluded as attention keys. Padded query targets have the same inactive mask and harmless singleton legal action as the original packer. An active causal query cannot attend later padded queries. Each original active feature, legal choice, previous action, offset and partial binding remains identical. The complete path loss masks all inactive terms, so no target-length normalization or stopping information is introduced. Padding does not fill unused dictionary rows, relabel source tokens, add observations, choose a path or repair failure.

This reasoning depends on the actual attention masks and zero-dropout architecture; floating-point kernels can differ with shape. Tiny CPU-double tests compare every active legal logit, whole-path loss and every parameter gradient for both dictionary-input roles, unequal paths and duplicated units at tolerance 2e-12. Horizon overflow is an explicit error. A 96M MPS stress test must still measure numeric agreement and memory over sustained varying source lengths after fixed packing. No long training is authorized solely by the finite CPU tests.

## Prospective stress comparison

SOURCE-ACTION-STATIC-001 has two fresh processes: fixed geometry retaining the backend cache, and fixed geometry clearing unused cache after every completed update once loss/packed tensors and parameter gradients are released. Both begin with a single common initial reference cleanup. Same seed, artificial episode stream, architecture, optimizer and clipping; no Latin, source archives, manuscript panels, held-out text or paid access. Every sixteenth update exercises maximum source length; other updates vary both record lengths and arbitrary keys. The original failed dynamic campaign is not rerun as a control.

Each arm receives exactly 256 random-only updates, four episodes per update. Observe tensor, driver and host memory after forward/backward/update/cleanup, not only every hundred steps. Require maximum driver <=8 GiB, host RSS <=4 GiB, and second-half maximum driver no more than 256 MiB above the maximum across steps 16–128. Initial and final SAME-weight short CPU-double dynamic-reference versus full static MPS packing must agree in legal logits and whole-path loss within .002. A passing stress test remains a finite admission, not a proof of unlimited stability.

Predeclare preference for fixed-retain if it passes; otherwise fixed-clear if it passes; otherwise no language campaign admitted. Both attempts retain errors and cannot retry, resume or extend. Any subsequent language experiment needs a new registration, exact published freeze, fresh seeds, the measured policy and explicit linkage to the original failure. It cannot relabel or continue SOURCE-ACTION-TRAIN-001.
