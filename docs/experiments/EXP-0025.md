# EXP-0025 — Generator-adversary for HYP-005 with harder iid falsifier

Registered **2026-09-21** **before** any evolutionary fitness scores or held-out diagnostic scores for this id. New experiment id. Successor to EXP-0019 (FAIL `iid_control_failed`). Does **not** alter EXP-0011–0024 thresholds. **Not** a Voynich decipherment and **not** a historical hoax proof.

Linked: R3 redesign; HYP-005; EXP-0019; NB-0022 match rule.

## Why a new id (not a rerun)

EXP-0019’s negative control was `iid_char` (train character unigram into validation-shaped pages). On that validation-sized sample it **matched** `zipf_slope_top500` and `adjacent_repeat_rate` under the frozen floors, so it separated on only **2/4** optimizable metrics and the run aborted as `iid_control_failed` without interpreting held-out.

**Change (harder iid falsifier):** replace `iid_char` with **`iid_uniform_fixedlen`**: each word is a fixed-length string of length **8** drawn from a **uniform** `a–z` alphabet (not the train unigram). Validation page shapes (line word-counts, Currier `L`) unchanged. This control is designed so a non-copy generator cannot accidentally match Zipf / adjacent-repeat under the same τ (probe design only; this registration freezes the control **before** the scored run).

**Unchanged vs EXP-0019:** optimizable metric set; held-out metric set; floors; τ = max(|T−R|, floor); match rule; search genome/budget structure; held-out never in fitness. Held-out gate remains **separate ≥ 2/3**. Do **not** lower τ after seeing scores.

## Question

Can evolutionary search over the same typed copy-mutate / self-citation family force ≥3/4 optimizable ZL3b surface matches, and then separate on ≥2/3 held-out diagnostics, **when** the iid sanity control is the harder `iid_uniform_fixedlen` falsifier?

## Pass rule (frozen before scores)

**PASS** iff **all**:

1. `iid_uniform_fixedlen` separates on **≥ 3 / 4** optimizable metrics
2. Winner matches **≥ 3 / 4** optimizable surface metrics
3. Winner **separates** on **≥ 2 / 3** held-out diagnostics

**FAIL** modes:

| Mode | Meaning |
| --- | --- |
| `iid_control_failed` | iid separates on <3/4 optimizable — stop; do **not** interpret held-out; do **not** weaken the iid rule after seeing scores |
| `surface_unmatchable` | iid ok (≥3/4 separate) but winner <3/4 optimizable — this generator family cannot force the selected surface match; HYP-005 **not killed** |
| `heldout_also_matched` | ≥3/4 surface and held-out separates on ≤1/3 — optimized generator also hits withheld structure |
