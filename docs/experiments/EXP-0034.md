# EXP-0034 — exact generator-weighted source-conditioned copy alignment

**Exploratory diagnostic on an exposed synthetic Polish set; registered before its weighted posterior scores.** This is not an unsupervised Voynich decoder or a fresh generalization test.

## Question and method basis

EXP-0033 found multiple string-compatible exact masks for every copy-mutate row, yet 91.7% of nonspace positions were forced when the true kept source was supplied. Does weighting those masks by the *actual corrected generator's* random merge and copy/mutate emission probabilities materially improve localization over EXP-0033's artificial uniform-alignment rule? This isolates one piece of path ambiguity. It does not isolate source inference in a model that sees only noisy text.

The generator is a variable-length insertion channel: one null event can emit one or two characters; with one null slot left, a two-character token is truncated. Conditional on a full pre-null source `S` and alphabet `A`, its recent-copy pool depends only on the consumed prefix of `S`. An exact finite-state, semi-Markov forward/backward calculation is therefore possible, rather than a generic string-alignment count. [Yu (2010)](https://www.sciencedirect.com/science/article/pii/S0004370209001416) describes variable-duration forward/backward inference, and [Statistical alignment based on fragment insertion and deletion models](https://academic.oup.com/bioinformatics/article/19/4/490/218888) is a precedent for probabilistic alignment under insertion/deletion mechanisms. Neither establishes a Voynich source process; our channel is the repository's known synthetic generator. Prior Voynich and ML limits: `docs/research/deep-review-2026-09-21/DECIPHERMENT.md`, `docs/research/PROTOCOL.md`, CHANNEL-ALIGNMENT-0001, EXP-0024, EXP-0030–0033. The old EXP-0024 stored-mask oracle is invalid for this true-channel question under the erratum.

## Inputs, exact conditioning and controls

Use only the **198** `copy_mutate` rows in the already exposed EXP-0032 Polish holdout JSONL SHA-256 `ee78f08814a993c42e0558e5028cfdaa4d1c1e2812c9e56d82585a1e8b255664`; clean Polish raw source SHA-256 `d5521a54c38616e4b2255af8fe8deb6e95f4428e721d140973c672a482b28b5c`, fixed generation seed320034, generator SHA from `data/manifests/exp0032_data.json`. Independently replay all600 rows to recover each copy row's **full** pre-null source before 128-character crop, and require byte-exact saved-row equality. This conditions on stronger oracle information than EXP-0033 (full `S`, its length, alphabet and visible retained-source count); no model can obtain this information from the noisy string alone.

For each row let `N=|S|`, `K=round(0.30/0.70 × N)`, `L=N+K`, and `T=min(128,L)`. Compute the exact likelihood and per-visible-position keep posterior of `X[:T]` under the generator, conditioned on `S`, alphabet, copy family, and the saved number of visible retained characters. If `L<128`, require the remaining visible characters to be deterministic signal-labeled padding spaces and condition on all `N` generated signal characters. If `L≥128`, marginalize the unobserved generator suffix, including a two-character null event that begins at observed position127 and ends outside the window. Conditioning on the retained count makes the visible retained string the known source prefix; verify this and the gold mask for every row. The `S`-conditioned merge probability uses remaining signal and null-character budgets; null emission integrates its uniform recent-signal copy, one-character mutation and two-character insertion branches, including truncation at `K=1` remaining. Do not approximate the channel by independent per-character null emissions.

Use log-space forward/backward and compute: conditional gold-mask posterior mass (summing alternative null-event segmentations); posterior keep probability for each visible position; and a fixed-retained-count top-posterior mask/null F1. Compare its copy-row mean F1 with the precomputed EXP-0033 uniform-alignment top-count mask on the **same rows**; report 2,000 paired row-bootstrap draws seed340034 and mean gain interval. The descriptive **material weighting gain** rule is mean gain≥0.02 and bootstrap lower bound>0; otherwise not supported. Report separately `L<128` and `L≥128`, mean/median gold-mask posterior probability, and model-vs-oracle values only with a warning about incomparable information. No EXP-0032 model is retrained or retuned.

Validate emission laws by probability sums, tiny exhaustive path enumeration, gold-support and marginal/count invariants, and a separately implemented auditor that independently replays source rows and recomputes all198 normalization, marginals, masks and aggregates. Audit pass is required for interpretation. Keep per-row result compact; raw sources stay ignored. CPU hard cap180s each runner/auditor, no paid API or external GPU. Registration, runner, auditor and tests must be committed/pushed and remote-verified **before** the first weighted posterior score. If exact computation or audit fails, record the failure; do not silently switch to an approximate or easier channel. No historical conclusion can follow directly from this synthetic study.
