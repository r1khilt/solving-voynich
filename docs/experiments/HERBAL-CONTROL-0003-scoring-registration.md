## Target and restrictions

The prediction target is **Commons historical chapter identity versus unknown**, not modern botanical species or Voynich meaning. For each query manuscript `q ∈ {BnF, Egerton, Casanatense}`, use the other two manuscripts as labeled galleries. Development contains 24 known and 12 deliberately absent chapter classes, evaluation contains a disjoint 24 known and 12 absent classes. Only the 24 known classes enter each gallery; unknown-class source images from those galleries are never included in that run. A given chapter appears as a query in all three directions, so 108 directional decisions come from only 36 independent evaluation classes. Extract and score the 108 development crops **first**, freeze/push all development-selected parameters and code, and only then extract the separate 108 evaluation feature prints. The selection routine must not accept an evaluation matrix or evaluation labels.

This design follows [Scheirer et al.'s open-world formulation](https://www.wjscheirer.com/projects/openset-recognition/) in permitting a reject decision and [Vaze et al.'s semantic-shift benchmark](https://www.robots.ox.ac.uk/~vgg/research/osr/) in comparing to strong ordinary classification and reporting hard unseen cases. Historical chapter tags can be wrong or synonymic. A visual match here is only retrieval of this metadata label under manuscript-style shift.

The local `herbal_control_0003_freeze.py` gate must verify all 216 downloaded source JPEGs, all 216 crop PNGs, both box manifests marked `complete-pre-score-manual-review`, and the exact source/panel membership, then write `data/manifests/herbal_control_0003_input_freeze.json` with SHA-256 for the full source and both image manifests. This complete freeze and its code must be committed and pushed before **either** split's feature extraction. The development-only Swift extractor and scorer both require its hash; the scorer parses only development class labels, while checking the evaluation image manifest by checksum without reading its labels. The current partial source/crop manifests deliberately fail this gate. The source and crop review must follow the [stage-1 eligibility and reserve rules](HERBAL-CONTROL-0003.md); any role-preserving reserve substitution needs a separately recorded panel amendment before this freeze.

## Fixed feature and class cost

Use macOS Apple Vision `VNGenerateImageFeaturePrintRequest` revision 2, `scaleFit`, on white-padded 512×512 crops, matching HERBAL-CONTROL-0002. Obtain Apple's `VNFeaturePrintObservation.computeDistance` for every query/gallery crop pair within each direction. This is one fixed opaque global feature, without training or data augmentation. Before comparing methods, divide distances for ordered query/gallery manuscript pair `(q,s)` by `m(q,s)`, the **median of all 36×24 cross-image distances in the development split for that pair**, including development unknown queries but excluding evaluation images. Require each median finite and positive. Reuse those six frozen medians unchanged on evaluation; do not normalize by evaluation distances, chapter labels, or the paired identity of an image. Thus a normalized query-to-reference distance is `d(q,s,i,c) = raw_distance(query_i, reference_{s,c}) / m(q,s)`.

For each query and one of the 24 gallery chapter classes, define four fixed class-cost families. `single_first` and `single_second` are the two `d` values in canonical manuscript order `BnF < Egerton < Casanatense`; `two_mean = (d_first + d_second)/2`; `two_min = min(d_first,d_second)`. The `min` rule tolerates a visually divergent source exemplar but may falsely accept unknowns; the `mean` requires both sources to agree. Metadata pairs the two source exemplars by chapter label. No source-source matching is required in the primary methods. All four families are compared using the **same reject-capable one-to-one batch decoder**, which is stronger than unconstrained nearest neighbor and directly addresses the HERBAL-CONTROL-0002 post hoc correction.

For one query manuscript and one split, construct a rectangular cost matrix with 36 query rows, 24 known-class columns and 36 distinct null columns. Every known-class cell has its class cost. Every null cell has a shared rejection penalty `τ`. Run minimum-cost linear assignment, with each row assigned exactly one column and each known class used at most once. A null assignment predicts `unknown`; a class assignment predicts its chapter name. Put null columns first and maintain canonical row/class order so exact ties are deterministic; report any **different predicted class/reject pattern** within `1e-9` total normalized cost rather than claiming a robust margin from it. Permutations among identical null columns do not count as different predictions. The null columns permit any number of rejects, including all 36, rather than forcing exactly 12. The exact same 24-class/36-query shape is used in development and evaluation.

## Development-only threshold and method choice

For each of the four cost families, pool all finite development **class costs** across the three query directions. Sort them, form the empirical quantiles at `k/200` for `k=0,…,200`, deduplicate them, and add one candidate strictly below the minimum (`0` if all costs positive, else `min−1`) and one strictly above the maximum (`max+1`). These are the only candidate `τ` values. For each candidate, decode the three development directions and compute macro balanced accuracy: for a direction, `BA_q = 0.5 × (correct_known_names/24 + correctly_rejected_unknowns/12)`; macro BA is the mean of the three `BA_q` values. For each family select the `τ` that maximizes development macro BA; tie chooses the smaller `τ` (more conservative rejection). Then choose the primary family with highest development macro BA; tie preference is `single_first`, `single_second`, `two_mean`, `two_min` in that order. Freeze the primary family, its `τ`, all six normalization medians and every source/crop hash before any evaluation score. This deliberately gives single-source methods the same threshold tuning and batch constraint as two-source methods.

Also report four **independent per-query** controls using each same cost family and its own development-selected `τ` from the same grid: choose the lowest-cost class only if its cost is strictly below `τ`, else reject. A top-class tie within `1e-7` rejects. These controls isolate the effect of one-to-one assignment. An optional unlabeled source-source pairing/cycle variant is secondary only and must be specified in a separate pre-score amendment with the same reject option and development-only tuning; it is not a substitute for the metadata-paired two-source baseline.

The hash-selected unknowns were **not selected as visually hard negatives**. A pre-score metadata-only replay of the name rule below finds only 2/12 near-name unknowns in development and 2/12 in evaluation. Chapter-name similarity is not a reliable proxy for illustration similarity, and this tiny stratum cannot establish hard-unknown robustness. Report it descriptively; a future separate hard-negative panel would need its own untouched source/image split and registration.

The subsequently registered [folio-order-only challenger](HERBAL-CONTROL-0003-folio-challenger.md) addresses a distinct metadata confound: matching by similar chapter positions across the three books. Its motivation involved inspection of evaluation *metadata* after this panel was frozen, explicitly disclosed in its document. It may veto a claim that image matching adds practical value beyond page-order alignment; it does not alter the image method, split, threshold or primary historical-image gate here.

## Final evaluation and claims

Run the frozen primary method once on the 36 evaluation queries in each manuscript direction. Report full confusion rows and, for every registered method, correct known chapter names `/24`, correctly rejected unknowns `/12`, unknown false-accept class labels, directional and macro BA, exact one-to-one assignments, rejection threshold, score margins and class-level errors. Do not hide failures where the query drawing and chapter metadata disagree. Mark unknowns as *near-name* when `1 − LevenshteinDistance(name, known_name)/max(len(name), len(known_name)) > 0.5` for at least one known chapter after Unicode case folding; this is a descriptive metadata stratum, not a tuned hard-negative selection or primary score. Report a 95% stratified class bootstrap interval for the primary macro BA and for paired BA differences: sample 24 known and 12 unknown evaluation classes with replacement, preserving all three directional predictions for each class, 10,000 replicates with seed `3003`. For the conservative two-source comparison, each bootstrap replicate compares against the better of the two single-source batch scores in that replicate.

The **historical-image open-set feasibility gate** requires the development-selected primary method to achieve macro `BA ≥ 0.80` on evaluation, and in **every** direction at least `18/24` correct known names and `10/12` correct unknown rejections. This gate was chosen before any evaluation image feature or score; it concerns only the fixed chapter metadata task. A **two-source benefit** is a separate claim, allowed only if the primary family is `two_mean` or `two_min`, its evaluation macro BA is at least `0.05` above **both** registered single-source batch methods, and the stratified paired-bootstrap 95% lower bound for its difference from the better single-source method is above zero. A **one-to-one benefit** is separately supported only when the chosen primary batch method beats its same-cost independent-query control by at least `0.05` macro BA with a positive paired-bootstrap lower bound. These claims can fail independently; a good raw retrieval result must not be mislabeled a cycle result.

No outcome of this control alone licenses naming a Voynich plant or opening reserved manuscript text. Historical source drawings, crops, manuscript style, iconographic conventions, category errors and synonymous chapter titles differ from a hypothetical Voynich depiction. A manuscript-facing hypothesis would require independent visual review, a frozen image rank with an explicit unknown option, an accountable word-level prediction and untouched physical-folio confirmation under `docs/research/PROTOCOL.md`.
