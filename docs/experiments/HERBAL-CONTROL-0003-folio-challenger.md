# HERBAL-CONTROL-0003: folio-order-only challenger

**Status: prospective, conservative diagnostic added before any image feature score.** The original image gate and split in [stage 1](HERBAL-CONTROL-0003.md) and [stage 2](HERBAL-CONTROL-0003-scoring-registration.md) remain unchanged. This challenger can only weaken a visual-specific interpretation, not rescue a failed image gate.

## Why this is necessary, and what was exposed

The three named copies have strongly aligned chapter order **within this frozen panel**. A metadata-only inspection of all 72 primary classes, including evaluation class identities, found Spearman folio-side rank correlations of 0.8432 for BnF–Egerton, 0.9215 for BnF–Casanatense and 0.8490 for Casanatense–Egerton; all 72 folio sides were unique within each manuscript. This inspection is an explicit exposure of **evaluation metadata**, although no new image pixel feature or evaluation accuracy was computed. The challenger is therefore a conservative diagnostic motivated after seeing the fixed panel; do not describe it as selected without evaluation-metadata knowledge. Its algorithm and any parameters must still be frozen before image features, and its evaluation score must remain unopened until the complete image/crop freeze and development selection are pushed.

The control answers a precise rival explanation: a researcher can align chapters across these manuscripts from page positions alone. If such a rule performs about as well as image matching, chapter-retrieval accuracy does not establish that botanical depiction matching was necessary. The page index is **not** an input to the fixed Apple Vision feature; this is a competing metadata method, not evidence that Vision literally reads folio numbers. Some crops retain writing, and iconographic, layout and chapter-order conventions can jointly aid retrieval. This is a known-answer historical-chapter control, not a Voynich label.

A later post-result check on the older six-class HERBAL-CONTROL-0002 panel found identical class order across all three manuscripts; a rank-only mapping scores 36/36 directed matches without image pixels. This was discovered **after** this larger-panel folio rule was registered. It reinforces the need for the prospective larger-panel comparison but does not change the registered fit, threshold grid, evaluation split or veto criterion. See `results/HERBAL-CONTROL-0002/folio_rank_exploratory.json` and NOTEBOOK NB-141.

## Frozen metadata-only method

For every panel source title, parse its `f.NNNr` or `f.NNNv` coordinate as integer `x = 2N + 1[v]`. Reject a missing or ambiguous coordinate; no page image or feature print is read. For each of the six ordered query→source manuscript pairs, use the **24 development-known matched chapter classes only** to fit a positive Theil–Sen affine map. Compute all 276 pair slopes `(y_j−y_i)/(x_j−x_i)` in canonical development class order, take their median as `a`, and take the median of `y_i−a x_i` as `b`. Stop if `a` is not finite and positive. The raw query-to-reference class distance is `|a x_query+b−x_reference|` in source folio-side units. This map is fixed for evaluation; neither development-unknown nor evaluation class identity may fit it.

For each ordered manuscript pair, divide raw distances by the median of **all 36 development queries × 24 development-known reference pages** for that pair. The six medians are finite/positive and frozen unchanged for evaluation. Use the identical `single_first`, `single_second`, `two_mean`, `two_min` class-cost families, canonical source order, 36-query/24-class/36-null minimum-cost batch assignment, independent-query controls, 201-quantile-plus-extremes threshold grid, macro balanced accuracy and tie rules fixed for the image method. Select the folio challenger family and rejection threshold on development only. No image feature, crop coordinate, drawing category or evaluation label enters the fitted map or threshold.

After the full 216-source/216-crop input freeze and the separate image development method selection are audited and pushed, score this *already fixed* folio rule on the disjoint 36 evaluation classes in three query directions. Report exact known-name `/24`, unknown-rejected `/12`, false accepts, macro BA and class-bootstrap uncertainty. The challenger is a **veto for a visual-specific value claim**: require the selected image method's evaluation macro BA to exceed the development-selected folio challenger's evaluation macro BA by at least 0.05 and a paired stratified class-bootstrap 95% lower bound above zero. If it does not, the original historical-image gate may still be reported as passed or failed on its own terms, but do not claim that this assay establishes a practical advantage over page-order alignment. A win over folio order still cannot prove pure botanical morphology use or identify a Voynich plant; explicit unknowns and independent manuscript-facing confirmation remain required.

The implementation must refuse partial input and avoid an evaluation mode until the complete freeze and both development selections are committed. Record the source commit, metadata parser, fit coefficients, medians, thresholds, exact split hashes, software versions and any failed numerical gate. A separate independent auditor should replay folio parsing, Theil–Sen fit and all final decisions; use no paid API.

## Prepared code and exact gates

`src/voynich/herbal_folio.py` implements the six positive development-known Theil–Sen maps and the directed raw folio-distance matrix. `scripts/herbal_control_0003_folio_features.py` refuses an absent/incomplete 216-page/216-crop input freeze and checks every selected crop hash. Its evaluation mode requires hash-linked, passing folio **feature** and **score** audits, plus the primary Apple image method's passing development score audit, before reading evaluation folio positions. The development maps come from the saved folio development feature artifact; evaluation cannot refit them. `scripts/herbal_control_0003_folio_feature_audit.py` independently parses source titles, recomputes the six maps using NumPy pair slopes, and checks all 11,664 directed distance cells. The development/evaluation score wrappers and independent assignment audits use the same four registered cost families, thresholds, null columns and uncertainty calculations as the primary image method, but preserve distinct folio IDs and a `folio_open_set_feasibility` field. Symmetry remains mandatory for Apple and DINO image distances; only the folio method permits directed matrices. Synthetic 108-row controls test affine-map recovery, split isolation, missing-input refusal, both evaluation locks, full matrix replay and tampered feature audit/score audit/crop rejection. No HERBAL-CONTROL-0003 folio or image score has been computed.
