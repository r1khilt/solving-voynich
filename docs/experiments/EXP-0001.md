# EXP-0001 — Implementation validation and bounded predictive pilot

Registered before manuscript-model training on 2026-09-20 PDT. Status: **completed**. This is an exploratory engineering pilot, not a confirmatory decipherment experiment or an architecture ranking.

## Question and scope

Can the pipeline acquire and parse a documented Voynich transcription, train a randomly initialized inspectable predictor without page/split leakage, persist a reproducible checkpoint, and execute faithful causal interventions? Related methods: M-002 and M-003. No historical hypothesis is accepted or rejected by this pilot.

## Fixed inputs and design

- Source: Zandbergen–Landini ZL3b IVTFF transcription, source SHA-256 `bf5b6d4ac1e3a51b1847a9c388318d609020441ccd56984c901c32b09beccafc`; see tracked data manifests and DATA.md.
- Metadata-stratified physical-leaf/foldout assignment version 2 is frozen before model evaluation: 177 training, 24 validation and 25 test pages; 112 vocabulary entries. An earlier uncommitted random assignment omitted whole sections from validation and was replaced using metadata only, before any model outcome. No outcome-based split reroll. All eight illustration types are represented in train/validation; test lacks astronomy because only two independent astronomical leaf groups exist.
- Vocabulary fitted to training pages. The predictor sees normalized EVA units and layout markers, never folio identifiers, Currier labels, scribal labels, editorial prose, plaintext, pretrained embeddings, or external language data.
- Ignore uncertain/unknown targets in every objective. Preserve their markers in context and source annotations in provenance.
- Primary prediction metric: validation bits per normalized EVA token, with the denominator and per-page counts reported. Never evaluate test loss during this pilot.
- Smoke: `configs/smoke.json`, seed 42, 40 steps, batch 4, context 64, CPU.
- Reference pilot: `configs/reference.json`, seed 42, **200 steps maximum**, batch 8, context 256, CPU unless availability testing justifies a recorded device change. Schedule/override recorded in run manifest.
- Compare validation unigram, five-gram, and local-copy/unigram baselines under the same 256-unit window policy as the reference.
- Optional variant correctness is covered by unit/gradient/causality tests. No multi-seed efficacy claim from this pilot; a subsequent registered ablation study is required.

## Implementation acceptance criteria

1. Parser/tokenizer preserve raw provenance, separate uncertainty from editorial annotations, and reject source/split drift.
2. No windows cross a page; physical groups remain within one split; train-only vocabulary; every eligible validation target scored once.
3. Future-token changes leave earlier predictions unchanged; explicit analysis and ordinary forward paths agree within float32 tolerance in evaluation mode; projected head results sum to the attention update.
4. Identity patches preserve outputs, controlled residual replacement recovers the matching clean computation, and architecture options receive gradients without future-label leakage.
5. A bounded toy test demonstrates optimization and checkpoint restoration; the real-data pilot reports rather than guarantees prediction improvement. Failure to beat the five-gram baseline is a useful result, not an implementation failure.
6. Save run provenance, checkpoint hashes, validation metrics, and intervention control results. Passing an intervention smoke test does not identify a circuit or plaintext.

## Resources and stopping

Local machine reports arm64, 64 GiB RAM and 18 logical CPUs. The sandboxed PyTorch probe reports no available CUDA/MPS, so start with four CPU threads. Expect minutes rather than hours for this bounded pilot; actual timing is recorded. No paid API calls or remote training. Stop on nonfinite loss/gradients, failed leakage/causality checks, validation patience, or the stated step budget. Do not expand the sweep just because a desired score was not reached.
