The audited dense source representation must pass DENSE-SOURCE-001 first. It uses
the identical large order12/minimum4/tau64source and original rho1/225. Alphabet,
unit family and record boundaries remain supplied. The decoder is not supplied
the true record length. Compare four arms:

1. **Original point key:** unchanged CONFIRM001learned key, exact per-record MAP.
2. **Fit-selected point key:** highest fitting posterior key in the full one-move
   bank, exact per-record MAP. This isolates neighborhood search under the source.
3. **Joint key/text MAP:** maximize `w_i * Q(x)` across all fitted positive-mass
   keys and text tuples compatible with both transfer records. Per-key first
   readings make this exact within the bank, subject to numerical checks.
4. **Marginal text MAP candidate:** maximize `Q(x) * sum_compatible w_i` over the
   union of per-key top8tuple lists, with the fixed next-score unseen upper bound.
   Use every positive fitting weight; zero-mass bank entries remain inventoried
   but need no inference. Retain open bounds as approximate results, with no k
   increase or rerun.

Arms3and4 share the same new ciphertext and key bank. This distinguishes combining
key support from the benefit of revising the key choice using new ciphertext.
Comparing arm4only to arm2would confound these effects. One key must explain both
records in arms3/4; source states reset between records, keys do not.
