# EXP-0041 post-score invariance amendment

**2026-09-25 PDT; after one failed scored runner invocation, before any published comparator result.** The original EXP-0041 registration, runner, auditor, tests and notebook were committed as `9f05a5f14bb89682e3714ce6247451407b9ce3e9`, pushed and remote-verified before running `PYTHONPATH=.:src .venv/bin/python -m voynich.readable_edge_calibration`. That invocation computed the panel in memory but stopped at `AssertionError: Substitution invariance failed for last_minus_shuffle_bits_per_pair`. It wrote **no** `results/EXP-0041/` directory or comparator JSON. The failure is retained in NB-179; no source result is treated as qualified.

**Diagnosis.** The estimator is equivariant under a fixed one-to-one glyph relabeling when the model is refitted: English and its bijective substitution have identical real last/first/identity log scores up to floating tolerance. However, the original code gave English shuffle seed `410400` and its bijective counterpart `414400`, following the per-view seed formula. These are two independent Monte Carlo draws from the same null distribution. Their 200-draw *sample means* need not be bitwise equal, so the registered exact-equality positive control mistakenly tested Monte Carlo noise, not cipher invariance. This was caught by the runner's own post-score guard, not by the independent auditor.

**Narrow amendment.** Keep all source files/hashes, window offsets, manuscript skeleton, candidate views, channel seeds, model, score, 200-shuffle count, and interpretation unchanged. Give the bijective control **the exact same 200 permutation seeds as plain English** (`410400`–`410599`); the other 19 views retain the original per-view seeds. Mirror this in the independent auditor. Add a toy test asserting the shared seed route. The original registration remains intact as the pre-score record; this document explicitly supersedes only its bijective-null seed sentence. Re-run the **entire** panel after committing/pushing/remote-verifying this amendment and code, rather than splicing scores from the failed process. The still-exposed validation split and lack of historical-language inference remain unchanged.
