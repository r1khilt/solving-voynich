# EXP-0032 result — large recurrence model helps modestly, but recovery gate fails

**Registered decision: NOT_SUPPORTED.** On a newly acquired Polish text, the first-occurrence (glyph-renaming-invariant) model improves copied-null localization over an equal-capacity raw-glyph model by **0.0241 null F1**, with a paired row-bootstrap 95% interval **[0.0171, 0.0312]**. The effect is positive at this exploratory resolution but misses the pre-registered **≥0.05** gain and **>0.02** lower-bound gates. Its mean copy reconstruction **0.1809** exceeds matched exact-count random **0.1384** by **0.0425**, short of the registered **>0.05** margin. No Voynich manuscript text, label, image or final holdout was scored.

## Design and frozen sequence

The [pre-result registration](EXP-0032.md) and [source-frozen code/data audit](../../results/EXP-0032/data_audit.json) were pushed as `5c92d795b74e7546bc06c8e7b03e649fc6b228ee` before training. The two-seed four-checkpoint validation selection and all four checkpoint hashes were pushed as `c2799f82797c46af00a664242e23b7128002a856` before the first Polish model score. Both conditions had the **same 10,746,629-parameter six-layer Transformer**, source windows, features, mask/world objective, 3,000 updates and two model seeds. The only difference was raw cipher-glyph IDs versus first-occurrence IDs, which exactly ignore arbitrary glyph renaming while preserving recurrence. Training used 12,000 English/Latin corrected-channel rows; validation used 1,200 later, source-separated rows. The held-out Polish source was Project Gutenberg #34635, with 600 nonoverlapping source blocks, including **198** copy-mutate examples. Its checksum, rights note, preprocessing and all derived-data hashes are in `data/manifests/exp0032_data.json`. A 600-row iid text/mask impossibility control and 20-seed matched random masks were evaluated in the same frozen pass.

All four 3,000-step MPS fits completed within their 600-second caps, **266.5–266.9 seconds each**, **1,066.86 seconds total**, with no paid API. The best validation copy-null F1/step pairs, selected without Polish access, were raw seed320101 **0.4603/3000**, canonical seed320101 **0.4859/2500**, raw seed320202 **0.4566/2500**, canonical seed320202 **0.4844/3000**. These earlier validation advantages motivated no change to the registered evaluation.

## Held-out observations

All scores below use the same fixed top-90-of-128 keep decoder. Null F1 measures per-position identification of inserted material; reconstruction measures whether the retained *ordered string* matches the known pre-null cipher and penalizes length errors. They answer different questions.

| Canonical, seed 320101 | 0.4810 | 0.1846 | 0.5548 | 0.9349 | 0.3011 |

| Matched random, 20-seed mean | 0.3067 | 0.1384 | 0.2951 | 0.2970 | 0.2963 |

Both large architectures clearly learned this *synthetic* periodic positive control (null F1 **0.935–0.948**, above the ≥0.70 competence gate). The iid impossibility control stayed near its exact-count random baseline: model null F1 **0.295–0.301** versus **0.296**, passing the no-leak rule. Canonical token IDs and copy-aware features were unchanged for all 600 Polish rows under a new full-pool bijection; direct output probability max difference was **0.0**, passing the invariance rule.

The paired copy null-F1 gain was **0.0240669**, row-bootstrap95% **[0.0170518,0.0311729]** (198 rows, two shared model seeds, 2,000 resamples, seed320320). The preregistered minimum was +0.05 and lower bound >0.02, so both gates fail. Canonical mean copy reconstruction **0.1809292** is above matched random **0.1384067** but does not clear its required +0.05 margin. On **none of the 198 copy examples** did any model recover the entire exact 128-position mask. For random-character nulls, canonical F1 exceeds raw in both seeds; for periodic nulls, all are already strong and differences are small or mixed. The gains therefore localize inserted characters somewhat better without recovering the full latent stream.

## Audit and implication

The separately frozen score auditor passed. It decoded and recomputed all **4,800** saved held-out masks, all family metrics, 20-seed random controls, the paired bootstrap and the registered decision; it independently replayed **56** model probability vectors with maximum CPU-versus-MPS absolute error **5.22×10⁻⁷**, and reproduced exact canonical output invariance on its own intervention. Evaluation JSON SHA-256 `94ad7865b60fdd6ca10bffa1b23f446768e32df99e007fae1c8d5c1cb7cbc5f3`; audit JSON SHA-256 `679b5eb85d932444db93ade8f6ff4337399848d4a503c0edc403217a5439ecc9`. The data audit had independently replayed **14,400** generated rows, including **8,450** true pre-null source checks. The full repository suite before training passed **1,124 tests, eight skipped and 23 subtests**; focused symmetry/model tests3/3, changed-file Ruff and compilation passed. Local model weights and bulk rows remain Git-ignored; exact checkpoint hashes are in the tracked training reports and freeze manifest.

This is meaningful architecture evidence: a hard invariance gives a small, repeatable advantage over a model with the same large capacity, and neither model beats chance on a task with no recoverable mask information. It is **not** a solution to the corrected copy channel, because the registered practical margins fail and exact masks remain unrecovered. It is also not evidence that the Voynich manuscript uses the synthetic channel or that historical glyph identities should be discarded. The next diagnostic is source-conditioned alignment ambiguity: given the *true* pre-null cipher stream as an oracle, count how many distinct keep masks can produce the observed string and how much of the gold mask is identifiable even then. This can separate alignment ambiguity from the model's inability to infer the source stream. It must be labeled exploratory on the now-exposed Polish set and must not be misdescribed as a Bayes-optimal oracle for the nonuniform copy-mutate generator.
