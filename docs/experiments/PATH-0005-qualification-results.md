# PATH-0005 qualification pilot: clean-answer failures are mostly format drift

**Scope:** CPU-only retrospective analysis of the already exposed PATH-0004 clean baselines. This is a diagnosis, not a new model-competence pass or a confirmation of PATH-0004's crossover. The predeclared diagnostic label is **mixed failure**: only 6/20 incorrect source/donor answers on the confirmation panel were exactly the alternate table object, below the registered 75% threshold for concentrated alternate-object errors. The other 14/20 were explanatory text instead of the required one-word answer.

| Split | Eligible two-hop pairs | Correct source outputs | Correct donor outputs | Incorrect outputs: alternate object | Incorrect outputs: other |
| --- | ---: | ---: | ---: | ---: | ---: |
| Discovery | 14/24 | 15/24 | 15/24 | 2 | 16 |
| Confirmation | 10/24 | 14/24 | 14/24 | 6 | 14 |

All 30 `other` outputs across the two splits begin a step-by-step explanation, for example `Start at **Nalu**. From Lookup 1` or `Starting with **Iram**, we apply **Lookup 1`. The campaign's `generate_field` default permits at most 12 generated tokens, so these outputs end before a final one-word answer could be evaluated. Two discovery outputs started `peach -> rabbit ...`; they contain a table object inside a longer explanation, but the frozen exact-answer scorer correctly rejects them. We **cannot tell** whether a longer generation would have concluded with the right object. The six confirmation alternate-object outputs are actual wrong-answer strings under the frozen scorer.

The surface-form association is large: the colon/`First table` template had 18/24 eligible pairs across both splits (10/12 discovery, 8/12 confirmation); the arrow/`Lookup 1` template had 6/24 (4/12, 2/12). On confirmation the colon template generated 20 expected and four alternate objects across its 24 source/donor outputs, with no explanatory outputs. The arrow template generated eight expected, two alternate, and 14 explanatory outputs. **This comparison is confounded:** each lexical bundle received only one template, so output words and names differ with prompt form. It is a credible format hypothesis, not a measured causal effect of punctuation or a proof that the model can execute two hops reliably.

The original PATH-0004 gate still fails: confirmation has only 10/24 eligible versus the required 12/24. In this pilot, every both-correct pair had different source/donor first tokens; the deficit was clean-answer competence, not token identity. Query slot and bundle breakdowns, literal outputs, source/donor classes, source hashes, and script registration hash are preserved in `results/PATH-0005-qualification/diagnosis.json`. The fixed controls and split dependencies remain as stated in PATH-0004; the 24 prompt pairs within each split are not independent samples.

**Implication for the next study:** qualify a fresh task format before spending compute on interventions. A model that starts narrating can fail a 12-token exact-output gate even if its latent lookup information is useful. The follow-up competence bar registered for any fresh two-split candidate is at least 18/24 eligible composed pairs and 11/12 copy records in each split. This CPU pilot cannot score that bar. A longer generation, a more constrained answer prefix, or a different prompt may be worth comparing on new calibration words, but none has been validated here. The original two-hop mechanistic result remains unconfirmed and says nothing about Voynich meanings.

Reproduction: `PYTHONPATH=src .venv/bin/python scripts/path5_qualification.py`; `.venv/bin/ruff check scripts/path5_qualification.py` passed. No model inference, GPU/MPS use, paid API, network, or manuscript scoring. The analysis uses the existing PATH-0004 baselines and frozen task generator; it does not modify those artifacts.
