# HERBAL-CONTROL-0003: large open-set historical-chapter control — source split

**Status: source metadata and class split frozen; images and scoring not yet frozen or run.** This document records a prospective data split, not an image-recognition result. The prior six-class [HERBAL-CONTROL-0002 result](HERBAL-CONTROL-0002-results.md) passed its narrow registered gate, but a simpler pairwise bijection scored 32/36 versus the three-way rule's 28/36. Its hand-selected, closed gallery cannot reject a novel chapter. The next question is whether an image method can both retrieve a *known historical chapter* and say **unknown** when that chapter is absent from the reference library. Even success would not identify a Voynich plant, word or language.

## Why this test and these sources

[Kaoua et al. (2021)](https://arxiv.org/pdf/2108.08109) show that cross-manuscript herb illustrations can be matched with local visual features, but their annotated correspondences, learned features and propagation are not replicated here. [Scheirer et al.'s open-world recognition work](https://www.wjscheirer.com/projects/openset-recognition/) formalizes the need for a reject outcome. [Vaze et al. (ICLR 2022)](https://www.robots.ox.ac.uk/~vgg/research/osr/) show why a strong ordinary classifier and visually similar unseen classes are indispensable controls. In Voynich research, [Zandbergen](https://www.voynich.nu/illustr.html) describes proposed plant parallels as uncertain; resemblance cannot become a crib by assertion. This study uses chapter labels from [Wikimedia Commons' Tractatus de herbis categories](https://commons.wikimedia.org/wiki/Category:Chapters_in_Tractatus_de_herbis) as *known-answer historical metadata*, not modern taxonomic truth.

The source collector `scripts/herbal_open_inventory.py` made and cached 18 read-only Commons API responses: three complete manuscript file-category member lists and 15 batches of file-page visible categories. Each response's URL, ignored cache path, byte size and SHA-256 are in `data/manifests/herbal_open_inventory.json` (SHA-256 `f6fcac85eaab9f882d1a0c6b0528bc2f03f1cb40f87cd8e662d3806768256d07`). It found **719 file pages**, **663** with a chapter tag, **442** distinct chapter tags, and **177** tags with a file page in each of BnF Latin 6823, BL Egerton 747 and Casanatense 459. Commons file pages can have *multiple* chapter tags; a tag does not say which image region corresponds to the chapter. The metadata snapshot is versioned by exact API-response hashes; file/page revision IDs and modern species labels are not part of this snapshot. The previous HTTP 429 attempt was discarded; this collection completed with a minimum eight-second interval between uncached requests.

`scripts/herbal_control_0003_select.py` froze a deterministic metadata-only class split in `data/manifests/herbal_control_0003_panel.json` (SHA-256 `fc2bd19a8eb25d16d8f8387a26b551e42c1f221a048d8f8b07a3f20f02c4b725`). It first excludes the nine chapter labels in HERBAL-CONTROL-0001/0002, requires exactly one unqualified full-folio JPEG per chapter in each of the three manuscripts, and excludes every page used in those previous controls. This leaves **151 eligible classes**. A lowest page-collision-degree, lexicographic greedy choice leaves **87 classes whose 261 source pages never repeat across classes**. A SHA-256 ranking with seed `HERBAL-CONTROL-0003-2026-09-24-v1` assigns 24 development-known, 12 development-unknown, 24 evaluation-known, 12 evaluation-unknown and 15 reserve classes. Neither new image pixels nor feature scores nor Voynich text were inspected when selecting the split. The two tracked manifests total under 300 KiB; bulk page images will remain ignored.

The separate `scripts/herbal_control_0003_audit.py` imports neither collector nor selector. It re-reads and hashes all 18 cached API responses, reconstructs every manuscript member and chapter tag, verifies the 177-way intersection, independently replays candidate exclusion, page-disjoint selection and SHA split, and checks all 261 selected page records against source metadata. It passed; compact `results/HERBAL-CONTROL-0003/source_audit.json` SHA-256 `eb990f402297b0d5a419a55875e06d53e08f88a2aeebb9ff52114a41520b7560`. This is a source/split audit, not visual accuracy evidence.

For each of the three manuscripts in turn, its **36** development/evaluation chapter drawings are queries. The other two manuscripts supply reference images for the **24 known** classes only; the **12 unknown** query classes are absent from both reference galleries. Thus the final evaluation has 24 known and 12 unknown queries in each of three manuscript directions, 108 decisions overall, with correlation across directions because the same 36 chapter classes recur. The development panel has the same shape. All 72 primary classes have one source page in each manuscript (216 page images/crops before exclusions); the 15 reserve classes are not downloaded unless a pre-score eligibility exclusion needs one.

## Image eligibility before any feature score

Download only the fixed page titles from Commons, preserving URL, title, bytes and SHA-256; target under 150 MiB total source JPEGs and stop on HTTP 429, non-JPEG data or the cap. Before calculating any model distance, mark each chapter-page illustration region once, crop it, and freeze page/crop hashes and rectangles. A reviewer must check that the region visibly corresponds to the *chapter on that folio* rather than adjacent writing or another chapter's drawing. Exclude a chapter if any manuscript page has no locatable drawing, a fundamentally ambiguous assignment among multiple drawings, a corrupt/unavailable source, or a contributor category inconsistent with the page's visible chapter location. Preserve every exclusion and reason. Replace in fixed role order with the next unused reserve class in its stored order, with no model-output or Voynich-input inspection; stop the assay if fewer than the prescribed role counts remain. A lone researcher's crop judgments are a limitation; historian review would be required for a semantic anchor.

## Scoring stage to freeze separately before extraction

The first reference feature will be the fixed Apple Vision revision-2 feature print used in HERBAL-CONTROL-0001/0002, on equally padded crops. This retains a strong continuity baseline without training on evaluation classes. A **stage-2 registration must fix exact crop padding, score normalization, single-source and two-source fusion formulas, independent versus batch one-to-one assignment with null/reject slots, development-only threshold selection, tie handling, metrics, uncertainty and pass/fail criteria before any new feature distance is computed**. In particular, any cycle-inspired unlabeled pairing must be compared against the stronger *metadata-paired two-reference* batch matcher with the *same* rejection facility. One-to-one matching alone, not cycle consistency, explained the prior gain over raw nearest-neighbor retrieval. Neither a post hoc threshold nor a selected visual example may be promoted to a confirmatory result.

The evaluation must report, by manuscript direction and pooled by chapter class: correct named-known retrieval, correct unknown rejection, false accepts, balanced accuracy, pairwise errors against the strongest development-selected single-source and two-source controls, and class-level uncertainty. An improvement on this historical control would only justify a *frozen ranked image hypothesis* for later manuscript-facing testing. Any Voynich plant identification would still need independent visual adjudication, alternative chapter/species readings, a constrained text prediction made before opening its reserved transcription, and a pristine held-out folio test. No f35v feature ranking or reserved text score is authorized by this source split alone.

Estimated local resources: up to 216 page JPEGs, under 150 MiB downloaded data, under 12 GiB RAM and no paid API. The actual acquisition, crop review, scoring runtime and costs will be logged separately. The exact page inventory and split are fixed now; stage-2 method choices and image eligibility remain pending and are not disguised as completed work.
